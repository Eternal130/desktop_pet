# 控制面板设计 (Java)

> 本文档描述 Java 控制面板的模块设计和闲时行为策略。
> 整体架构参见 [架构总览](./00-架构总览.md)，通信协议参见 [通信协议](./03-通信协议.md)。

---

## 一、模块概览

### 1.1 UI层

提供用户交互界面，包括：

- **主界面**：宠物当前状态显示、快捷操作按钮
- **设置面板**：音量调节、模型选择、行为配置、启动项设置、拖拽模式切换
- **系统托盘**：最小化到托盘、右键菜单
- **宠物管理**：模型切换、模型导入

### 1.2 业务逻辑层

- **状态管理器 (State Manager)** ：维护宠物配置和运行时状态。MVP 阶段不实现心情/活力/好感度等养成属性，闲时行为从模型可用动作中随机选择。架构预留权重打分扩展，未来可根据状态属性值计算动作权重
- **交互处理器 (Interaction Handler)** ：接收渲染器上报的点击事件，根据点击区域和模型行为映射配置决定响应逻辑
- **定时任务 (Scheduler)** ：定期触发闲时动作等
- **配置管理器 (Config Manager)** ：持久化用户设置，支持导入导出（详见 [系统设计 - 配置文件](./05-系统设计.md)）

### 1.3 通信层 (Network Layer)

提供 WebSocket 客户端，封装消息发送和接收逻辑。实现消息分发机制，将不同类型的消息路由到对应的处理器。包含心跳检测和自动重连机制。断连期间缓存关键指令（如 `load_model`），重连后重发（详见 [系统设计 - 容错](./05-系统设计.md)）。

### 1.4 进程管理器 (Process Manager)

负责启动和监控渲染器进程。在自身关闭时确保渲染器进程一并退出（避免孤儿进程）。支持渲染器崩溃后的自动重启，重启后恢复模型和窗口位置（详见 [系统设计 - 容错](./05-系统设计.md)）。

## 二、闲时行为设计

### 2.1 MVP 方案

MVP 阶段不实现宠物养成状态系统（心情/活力/好感度）。闲时行为采用简单随机策略：

```plain
定时任务触发（Scheduler）
     │
     ▼
从模型可用的闲时动作池（idle_motions）中随机选择一个
     │
     ▼
下发 play_motion 指令到渲染器
```

### 2.2 扩展预留

架构预留权重打分决策机制，未来引入状态系统后：

```plain
定时任务触发
     │
     ▼
获取当前状态属性（心情、活力、好感度...）
     │
     ▼
为每个候选动作计算权重分
  - 心情高 + 活力高 → 欢快动作权重高
  - 心情低 + 活力低 → 打瞌睡/委屈动作权重高
     │
     ▼
加权随机选择动作
     │
     ▼
下发 play_motion 指令
```

状态数据支持持久化（关闭应用后下次启动可从上次状态继续），具体状态属性和衰减规则待未来版本设计。
