## 一、点击事件处理流程

### 1.1 MVP 事件流向

MVP 阶段渲染引擎独立处理点击事件，不涉及外部通信：

```plain
用户点击屏幕
     │
     ▼
┌─────────────────────────────────────────┐
│  GLFW 窗口接收鼠标事件                   │
│  (获取屏幕坐标)                          │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  交互处理层：坐标转换                    │
│  (屏幕坐标 → 模型本地坐标)               │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  Cubism SDK HitTest                     │
│  (检测点击了哪个 HitArea)                │
│  - Head (头部)                          │
│  - Body (身体)                          │
│  - Face (脸部)                          │
│  - ...                                  │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  渲染器直接处理反馈                      │
│  - 根据 HitArea 查找对应动作组           │
│  - 播放点击动画                          │
│  - 触发表情变化                          │
└─────────────────────────────────────────┘
```

> **MVP 简化**：HitArea 到动作组的映射硬编码在渲染器中（如 Head → TapHead、Body → TapBody）。后期由控制面板通过 `model_config.json` 动态配置。

### 1.2 Phase 2 事件流向（引入控制面板后）✅ 已实现

```plain
渲染器处理即时反馈（同 MVP）
     │
     ▼
EventEmitter 上报事件到控制面板
  type: "event", action: "hit"
  payload: { area_id, x, y, button }
     │
     ▼
控制面板（controller_qt）路由到实例的 hit 事件处理器
     │
     ▼
InteractionHandler 处理（挂载语音包时由 MountedBehaviorEngine 优先处理）
  ├─ 查找命中区域→动作映射（3 级大小写容错查找：兼容渲染器小写 key
  │   如 "head" 与 PascalCase 映射如 "Head"）
  └─ 构建 play_motion 指令（Protocol 命令工厂）→ 经 WsServer 发送给渲染器
```

### 1.3 设计要点

**即时反馈由渲染器处理**：用户点击后需要立即看到反馈，这一原则在 MVP 和完整版本中一致。MVP 中渲染器是唯一处理方，Phase 2 引入控制面板后渲染器仍负责即时反馈，控制面板负责后续业务逻辑。

## 二、拖拽行为设计

### 2.1 拖拽跟随模式

支持两种拖拽跟随模式：

| 模式 | 说明 | 体验 | MVP |
|:---|:---|:---|:---:|
| **直接跟随** | 窗口位置 = 鼠标位置 - 点击偏移量 | 精确、无延迟 | ✓（默认） |
| **物理惯性** | 窗口以弹性动画跟随鼠标，带惯性和阻尼效果 | 生动、有趣味 | ✓ |

> **MVP**：拖拽模式硬编码（默认直接跟随），后期由控制面板设置面板切换。

### 2.2 MVP 拖拽流程

```plain
用户按住模型
     │
     ▼
┌─────────────────────────────────────────┐
│  渲染器检测到鼠标按下 + 拖拽             │
│  - 记录点击偏移量                        │
│  - 不切换动作（保持当前动作）             │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  持续拖拽                                │
│  - 根据跟随模式更新窗口位置              │
│  - 直接跟随：窗口即时到位                │
│  - 物理惯性：弹性动画追随鼠标            │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  用户释放鼠标                            │
│  - 窗口停在释放位置                      │
└─────────────────────────────────────────┘
```

> **Phase 2 已实现**：拖拽开始/结束时上报 `drag_start` / `drag_end` 事件到控制面板。`drag_end` 事件包含窗口最终位置（`window_x`、`window_y`，通过 `glfwGetWindowPos` 获取），控制面板将位置持久化到实例配置。

### 2.3 设计要点

- **释放后行为**：窗口停在释放位置，不做贴边吸附或重力下落
- **拖拽动作**：拖拽期间不播放特殊动作，保持当前动作继续
- **位置记录**（✅ 已实现）：每次拖拽结束后，控制面板从 `drag_end` 事件提取 `window_x`/`window_y`，持久化到实例配置（`instances/{uuid}.json`，QSaveFile 原子写入）
- **拖拽状态防护**（✅ 已实现）：控制面板维护拖拽状态标志。仅在收到 `drag_start` 设置标志后，后续的 `drag_end` 才会触发位置持久化。防止简单点击（未拖拽）被误判为 `drag_end` 并覆盖位置
- **wasDragging 捕获**：渲染器端在 `LAppDelegate` 中，先捕获 `_isDragging` 状态再将其置 `false`，确保 `drag_end` 事件仅在真正拖拽后发出
