# controller_qt 人工 UI 测试文档

> **文档目的**:对 Qt 控制面板(controller_qt)进行端到端的人工 UI 验证,覆盖
> `docs/controller_qt/development-plan.md` 中 Phase 4–9 的全部 UI 验收标准。
>
> **配套代码测试**:`controller_qt/tests/`(44 个 QTest 二进制)覆盖单元/集成层;
> 本文档聚焦**只有人眼+人手才能验证**的视觉、交互、跨进程、跨会话行为。
>
> **自动化批次**:`controller_qt/tests/ui_automation/run_ui_tests.py` 已自动化
> 本文档的 11 个用例(TC-4.1/4.7/4.9/4.10/4.11/4.12/5.6/9.2/9.5/9.6/9.7),
> 依赖 `--screenshot` CLI 模式;其余用例仍需人工。已有自动化结果见
> `docs/controller_qt/results/qt-ui-test-result-20260821-auto.md`。
>
> **测试前置**:Phase 0–3(通信层/进程编排/配置)的底层正确性由 QTest 保证,
> 本文档不重复验证底层协议字节;但在 UI 操作触发协议时,会用日志面板作为可观察
> 证据来交叉验证。

## 一、测试环境与准备

### 1.1 必备前置

| 项目 | 要求 | 验证命令 |
|:---|:---|:---|
| 构建 | `python build.py qt` 成功 | `build\bin\desktop-pet-controller-qt.exe` 存在 |
| 渲染器 | `python build.py renderer` 成功 | `build\bin\desktop-pet-renderer.exe` 存在 |
| 模型 | `build\bin\Resources\Models\` 至少有 1 个模型 | 见下表 |
| 端口 | 9001 未被占用 | `netstat -ano | findstr :9001` 返回空 |
| 系统托盘 | Windows 全版本可用;Linux 需 X11 + SNI 支持 | 任务栏右下角能看到图标 |

### 1.2 测试时可用模型(本机)

```
giwa-idol2023, Haru, Hiyori, jinse-specialB, Mao, Mark, Natori, Ren, Rice, Wanko
```

**推荐**:Hiyori(简单稳定)、Haru(动作丰富)、Wanko(表情多)。

### 1.3 配置目录位置

| 平台 | 路径 |
|:---|:---|
| Windows | `%USERPROFILE%\.config\desktop-pet\` |
| Linux | `~/.config/desktop-pet/` |

关键文件:
- `panel.json` — 窗口几何、主题、实例列表、PanelConfig 行为字段(含 notifications_enabled/notification_duration_ms)
- `instances\<uuid>.json` — 每实例配置(24 字段,含 dialogue_pack;原 7 个字幕字段已移除)
- `hit_area_cache.json` — hit 区域缓存

### 1.4 干净状态准备(每个测试章节前按需执行)

```powershell
# 备份后清空(测试前)
Rename-Item "$env:USERPROFILE\.config\desktop-pet" "desktop-pet.bak.$(Get-Date -Format yyyyMMddHHmmss)" -ErrorAction SilentlyContinue

# 或者只删 panel.json,触发首次运行流程
Remove-Item "$env:USERPROFILE\.config\desktop-pet\panel.json" -ErrorAction SilentlyContinue
```

### 1.5 启动命令

```powershell
# 从项目根目录
& ".\build\bin\desktop-pet-controller-qt.exe"

# 携带调试日志(若需要)
$env:QT_LOGGING_RULES="*=true"
& ".\build\bin\desktop-pet-controller-qt.exe"
```

### 1.6 日志位置

`%USERPROFILE%\.config\desktop-pet\logs\desktop-pet-controller-qt.log`(spdlog 轮转)。
日志格式样例:`[2026-07-19 14:23:01.123] [info] [InstanceSession@256] loading model Hiyori`。

### 1.7 测试通过/失败判定

- **PASS**:全部"预期结果"项出现,无未预期崩溃/卡顿/异常窗口。
- **FAIL**:任一"预期结果"未出现,或出现未预期行为(报错对话框、闪退、僵尸进程)。
- **N/A**:平台不支持的项目(如 Linux GNOME 无托盘)记录跳过原因。

## 九、已知缺陷与平台限制

测试时遇到以下情况属于**已知限制**,**不算 bug**:

| ID | 描述 | 影响 | 缓解 |
|:---:|:---|:---|:---|
| L1 | Linux GNOME 默认无 SNI,系统托盘不显示 | 托盘功能全部失效 | 装 AppIndicator / KStatusNotifierItem 扩展;设置页有提示 |
| L2 | Linux Wayland 透明窗口异常 | 渲染器窗口背景非透明 | 用 X11 会话(GNOME on Xorg / Xfce) |
| L3 | Linux Wayland 全局快捷键不工作 | Shift+drag / Ctrl+scroll 可能失效 | X11 下使用 |
| L4 | SchedulerTest 在 ctest 并行下偶发 flake | 仅测试,生产不影响 | 单独 `ctest -R SchedulerTest` 通过即可 |
| L5 | WsServerMultiTest 在并行下偶发 sendTextMessage=0 | 仅测试,生产不影响 | 单独跑通过 |
| L6 | Voice Pack UI 在详情页是 placeholder | 挂载需手改 JSON | 通过 MountedBehaviorEngine 自动驱动 |
| L7 | 详情页 "Idle Interval" 是显示型,无 UI 修改入口 | 需手改 JSON | 待新增 UI(发现的需求) |

## 十、测试结果记录

### 10.1 使用流程

1. 复制 [`qt-ui-test-result-template.md`](./qt-ui-test-result-template.md) 为同目录下的
   `qt-ui-test-result-YYYYMMDD.md`(例如 `qt-ui-test-result-20260721.md`)。
2. 按本文档第二章至第八章执行各 TC。
3. 在结果文档第三章勾选每个 TC 的结果(`PASS` / `FAIL` / `N/A` / `BLK`)。
4. FAIL 用例填入结果文档第四章(每条一个 FAIL-N 区块,含严重等级、复现步骤、日志关键行、证据路径)。
5. N/A 与 BLK 用例填入第五章。
6. 性能数据(COLD_START_MS、闲置内存、1 小时稳定性)填入第七章。
7. 完成后填写第八章签字与发布建议。

### 10.2 模板文档包含的章节速览

| 章节 | 用途 |
|:---|:---|
| 一、测试元信息 | 日期、测试人、git commit、环境(OS / 缩放 / Qt 版本 / GPU 等) |
| 二、结果总览 | 按 Phase 汇总 PASS/FAIL/N/A/BLK + 严重等级分布 + 一句话结论 |
| 三、详细结果 | 74 个 TC **全部预填 ID + 标题**,只需勾选结果 |
| 四、失败用例详情 | 复制式 FAIL-N 模板块(严重等级 P0–P3、复现率、日志、截图、建议处理) |
| 五、跳过 / 阻塞原因 | N/A 清单 + BLK 阻塞链(标注阻塞来源) |
| 六、新发现的需求 | 新增需求 / 改进建议 / 偶发现象 三张表 |
| 七、性能观察 | 冷启动 3 次取平均、闲置内存 3 时间点、1 小时稳定性 5 检查点 |
