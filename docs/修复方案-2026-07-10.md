## P1.3 — ProcessManager 线程修复（3 项）

| 项 | 值 |

| 风险 | 低-中 |

### P1.3a — ProcessManager 字段加 volatile

**问题：** `process`、`exitCallback`、`shutdownCommandSender` 非 volatile，在 `process.onExit()` 回收线程中被读取。

**修复（ProcessManager.java:33-35）：**
```java
// 修改前
private Process process;
private Runnable shutdownCommandSender;
private Consumer<Integer> exitCallback;

// 修改后
private volatile Process process;
private volatile Runnable shutdownCommandSender;
private volatile Consumer<Integer> exitCallback;
```

### P1.3b — raw new Thread() 改用托管执行器

**问题：** `ProcessManager.java:122` 裸 `new Thread().start()` 播放渲染器日志，违反 AGENTS.md。

**修复：** 添加一个单线程 daemon executor 字段，用于日志泵：
```java
// 类字段
private final java.util.concurrent.ExecutorService logExecutor =
    java.util.concurrent.Executors.newSingleThreadExecutor(r -> {
        Thread t = new Thread(r, "renderer-log");
        t.setDaemon(true);
        return t;
    });

// startRenderer 中替换裸 Thread
logExecutor.submit(() -> {
    try (BufferedReader reader = new BufferedReader(
            new InputStreamReader(process.getInputStream()))) {
        String line;
        while ((line = reader.readLine()) != null) {
            log.info("[renderer] {}", line);
        }
    } catch (IOException ignored) {
        // 流关闭时正常退出
    }
});
```
在 stopRenderer 末尾关闭 executor：`logExecutor.shutdown();`

### P1.3c — monitorExecutor 防重调度

**问题：** `MainWindowController.startMonitorPolling()` 无重入防护，重复打开 Monitor 标签页导致重复 `scheduleAtFixedRate`。

**修复（MainWindowController.java:2135-2150）：** 添加 `ScheduledFuture<?>` 字段追踪当前轮询任务：
```java
// 类字段
private java.util.concurrent.ScheduledFuture<?> monitorTask;

// startMonitorPolling() 中
public void startMonitorPolling() {
    if (monitorExecutor == null || monitorExecutor.isShutdown()) {
        monitorExecutor = Executors.newSingleThreadScheduledExecutor(r -> {
            Thread t = new Thread(r, "monitor-executor");
            t.setDaemon(true);
            return t;
        });
    }
    // 取消已有任务，避免重复调度
    if (monitorTask != null && !monitorTask.isDone()) {
        monitorTask.cancel(false);
    }
    if (currentInstance != null) {
        currentMonitoredInstanceId = currentInstance.getId();
    }
    lastStatsStateReceivedMs = System.currentTimeMillis();
    monitorTask = monitorExecutor.scheduleAtFixedRate(
            this::monitorTick, 0, MONITOR_POLL_INTERVAL_MS, TimeUnit.MILLISECONDS);
    log.info("Monitor polling started for instance {}", currentMonitoredInstanceId);
}
```

### P1.3d — performFullShutdown 移出 FX 线程

**问题：** `performFullShutdown` 在 FX 线程串行 `stopInstance`，每个最长阻塞 5 秒。

**修复：** 将实例停止移至后台线程，FX 线程仅负责 `Platform.exit()`：
```java
public void performFullShutdown() {
    saveState();
    stopMonitorPolling();

    // 后台线程停止所有实例（不阻塞 FX 线程）
    Thread shutdownThread = new Thread(() -> {
        for (PetInstance instance : instances) {
            if (instance.isRunning()) {
                stopInstance(instance);
            }
        }
        schedulers.values().forEach(Scheduler::shutdown);
        schedulers.clear();
        dispatchers.clear();
        if (wsServer != null) {
            try {
                wsServer.stop(1000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
        Platform.exit();
    }, "shutdown");
    shutdownThread.setDaemon(true);
    shutdownThread.start();
}
```

> **注：** `stopInstance` 内部调用 `pm.stopRenderer()`（含 Thread.sleep 忙等）。这是 P1.3 的一部分但属于 stopRenderer 的等待逻辑，后续可用 `process.waitFor(5, TimeUnit.SECONDS)` 替代 Thread.sleep 循环。此处先解决 FX 阻塞，Thread.sleep 本身保留（在后台线程中可接受）。

## P1.4 — mvnw.cmd 去硬编码

| 项 | 值 |
|---|---|
| 文件 | `controller/mvnw.cmd` |
| 风险 | 低 |
| 类型 | 构建可移植性 |

**问题：** 手写脚本硬编码 `JAVA_HOME` 和用户特定 Maven 缓存路径。其他开发者/CI 必失败。

**修复：** 使用环境变量优先 + 多级回退：
```bat
@REM Maven Wrapper for Desktop Pet Controller
@REM Uses JAVA_HOME from environment; delegates to MAVEN_HOME or mvn on PATH
@echo off
setlocal

REM --- JAVA_HOME resolution (prefer env, fallback to common install) ---
if not defined JAVA_HOME (
    if exist "C:\Program Files\OpenLogic\jdk-21.0.8.9-hotspot" (
        set "JAVA_HOME=C:\Program Files\OpenLogic\jdk-21.0.8.9-hotspot"
    ) else (
        echo ERROR: JAVA_HOME is not set and no fallback JDK found.
        echo   Set JAVA_HOME to your JDK 21 installation directory.
        exit /b 1
    )
)

REM --- Maven resolution (MAVEN_HOME > mvn on PATH > error) ---
if defined MAVEN_HOME (
    call "%MAVEN_HOME%\bin\mvn.cmd" %*
    exit /b %ERRORLEVEL%
)

where mvn >nul 2>nul
if %ERRORLEVEL% equ 0 (
    call mvn %*
    exit /b %ERRORLEVEL%
)

echo ERROR: Maven not found.
echo   Set MAVEN_HOME or ensure mvn is on PATH.
exit /b 1
```

**验证：** 在不同 JAVA_HOME 设置下运行 `mvnw.cmd -version`。

## P2.8 — 路径穿越净化

| 项 | 值 |
|---|---|
| 文件 | `renderer/src/network/CommandHandlers.cpp` |
| 风险 | 低 |
| 类型 | 安全纵深防御 |

**问题：** `load_model` 的 `model_path` 未净化；`play_motion_ext`/`play_audio` 接受任意绝对路径。

**修复：** 添加路径校验辅助函数 + 在各 handler 入口校验：

```cpp
// CommandHandlers.cpp 文件顶部（namespace Network 内）
// 校验模型短名：禁止路径分隔符、..、绝对路径前缀
static bool isValidModelName(const std::string& name) {
    if (name.empty() || name.size() > 256) return false;
    if (name.find("..") != std::string::npos) return false;
    if (name.find('/') != std::string::npos || name.find('\\') != std::string::npos) return false;
    if (name.front() == '~') return false;
    return true;
}
```

- `load_model`（第 46 行后）：`if (!isValidModelName(modelPath))` → 返回 1001 错误
- `play_motion_ext`/`play_audio`：接受绝对路径（语音包功能需要），但拒绝含 `..` 的路径：
```cpp
static bool isSafeFilePath(const std::string& path) {
    if (path.find("..") != std::string::npos) return false;
    return true;
}
```
