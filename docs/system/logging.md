# 日志体系

> 系统设计概述参见 [系统设计](./README.md)，整体架构参见 [架构总览](../README.md)。

---

## 一、设计原则

- 两端统一使用结构化日志，便于问题排查
- 日志输出到文件和控制台，文件按大小轮转
- 日志级别可通过配置文件动态调整，无需重新编译/重启

---

## 二、日志框架

| 端 | 框架 | 说明 | 阶段 |
|:---|:---|:---|:---:|
| C++ 渲染引擎 | `LAppPal::PrintLogLn` | Cubism SDK 内置日志函数（基于 `CubismFramework::CubismLogFunction` 回调），输出到控制台（printf）。当前未引入独立日志库，后期可考虑转发到 spdlog 以支持文件输出和轮转 | ✅ MVP |
| Java 控制面板 | SLF4J 2.0.17 + Logback 1.5.32 | SLF4J 门面解耦日志 API，Logback 提供实现。生产环境输出到文件（10MB 轮转，保留 5 天），测试环境仅输出到控制台（`logback-test.xml` 自动覆盖） | ✅ Phase 2 |

---

## 三、日志级别定义

| 级别 | 适用场景 | 示例 |
|:---|:---|:---|
| ERROR | 影响功能的错误，需要关注 | 模型加载失败、WebSocket 连接异常断开、音频播放器初始化失败 |
| WARN | 异常但可恢复的情况 | 重连尝试、配置字段缺失使用默认值、非关键指令丢弃 |
| INFO | 关键业务节点 | 启动完成、模型切换、WebSocket 握手成功、渲染器进程启动/退出 |
| DEBUG | 开发调试信息 | 消息收发内容、状态变更详情、定时任务触发 |
| TRACE | 高频细粒度信息 | 每帧渲染耗时、鼠标坐标变化、参数引擎每帧计算值 |

## 四、日志文件管理

| 项目 | 配置 |
|:---|:---|
| 存储路径 | `~/.config/desktop-pet/logs/` |
| 文件命名 | `renderer.log`（C++ 端）、`controller.log`（Java 端，后期） |
| 轮转策略 | 单文件上限 10 MB，保留最近 5 个归档文件 |
| 默认级别 | Release 构建默认 INFO，Debug 构建默认 DEBUG |
| 控制台输出 | Debug 构建同时输出到控制台，Release 构建仅文件 |

## 五、关键日志点

**渲染引擎（C++）— MVP**：

- 引擎初始化（OpenGL 版本、窗口参数、Cubism SDK Core 版本 `csmGetVersion()`、支持的最高 moc3 版本 `csmGetLatestMocVersion()`）
- 模型加载（路径、耗时、资源数量）
- 动作/表情切换
- 点击检测命中（HitArea 名称）
- 帧率变化（自适应帧率切换时记录）
- 错误及异常（含错误码）

**Phase 1 增加**：

- WebSocket Client 连接控制面板（连接地址、连接结果）

**Phase 3 增加**：

- 音频播放开始/结束
- 音频映射加载（接收映射配置）

**控制面板（Java）— Phase 2**：

- 应用启动/关闭
- 配置文件加载（路径、关键配置值）
- WebSocket Server 启动（监听端口）、客户端连接/断开（含渲染引擎连接状态变化）
- 渲染器进程启动/退出（含退出码）
- 指令发送（action + id，DEBUG 级别含完整 payload）
- 事件接收（action + id）
