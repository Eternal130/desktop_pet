# 渲染引擎设计 (C++)

> 本文档描述 C++ 渲染引擎的模块设计、音频架构和性能策略。
> 整体架构参见 [架构总览](./00-架构总览.md)，通信协议参见 [通信协议](./03-通信协议.md)。

---

## 一、模块概览

### 1.1 核心引擎层 (Core Engine)

负责整个渲染引擎的生命周期管理，协调各子系统工作。包含配置加载、初始化顺序、主循环控制和优雅关闭。

### 1.2 模型管理器 (Model Manager)

负责 Live2D 模型的加载和生命周期管理。通过 Cubism Native SDK 解析模型文件（.model3.json），加载纹理、动作、表情等资源。支持模型切换（加载新模型时自动替换当前模型）和预加载。不存在独立的"卸载"操作——模型切换时隐含卸载旧模型。

### 1.3 动画控制器 (Animation Controller)

管理模型动作的播放队列、优先级和混合。支持动作中断、循环播放和过渡效果。处理表情状态切换。

### 1.4 参数引擎 (Parameter Engine)

控制模型参数的实时更新，包括眼球跟踪（鼠标位置）、呼吸动画、自然晃动等。支持参数插值和权重混合。

### 1.5 交互处理层 (Interaction Layer)

处理鼠标事件（点击、拖拽、悬停），通过 Cubism SDK 的 HitTest 功能检测用户点击了模型的哪个区域（如头部、身体等），并将事件上报给控制面板。支持窗口拖拽移动（详见 [交互设计](./04-交互设计.md)）。

### 1.6 窗口管理层 (Window Management)

使用 GLFW 创建无边框、透明背景、始终置顶的窗口。

**平台支持策略**：
- **MVP 阶段**：Ubuntu 桌面版，仅支持 X11 窗口系统
- **后期扩展**：Windows（DWM）、macOS（NSWindow）、Wayland

> 注意：Wayland 对"始终置顶"和"透明背景"的支持存在限制，暂不纳入 MVP。

### 1.7 通信层 (Network Layer)

提供 WebSocket 服务端，接收控制面板指令并解析，将渲染器事件上报给控制面板。支持多客户端连接（预留多控制面板场景）。

## 二、音频播放架构

### 2.1 音频类型分析

Live2D 模型的音频有两种存在形式：

| 形式         | 说明                   | 同步需求           |
| :--------- | :------------------- | :------------- |
| **模型绑定音频** | 动作文件中定义的音效（如说话、点击反馈） | 高，需要与口型/表情精确同步 |
| **独立音频**   | 背景音乐、环境音效，与模型无直接关联   | 低，可独立播放        |

### 2.2 设计决策

**模型关联音频由渲染器播放**，理由如下：

| 考量因素  | 渲染器播放        | 控制面板播放     |
| :---- | :----------- | :--------- |
| 音画同步  | ✓ 精确同步，无网络延迟 | ✗ 需要额外同步机制 |
| 动作触发  | ✓ 与动作状态机天然耦合 | ✗ 需额外传递时间戳 |
| 实现复杂度 | ✓ 直接调用音频API  | ✗ 同步逻辑复杂   |
| 音量控制  | ✓ 接收指令即可     | ✓ 天然支持     |

### 2.3 音频模块架构

```plain
┌─────────────────────────────────────────────────────────┐
│              渲染引擎音频播放器                          │
│  ┌─────────────────────────────────────────────────┐   │
│  │  音频资源管理                                     │   │
│  │  - 加载模型内置音频 (.motion3.json 中定义)       │   │
│  │  - 缓存音频数据                                   │   │
│  │  - 格式支持 (WAV/MP3/OGG)                        │   │
│  └─────────────────────────────────────────────────┘   │

│  │  播放控制                                         │   │

│  │  - 音画同步 (时间戳对齐)                          │   │

│  └─────────────────────────────────────────────────┘   │
```

## 三、性能设计

### 3.1 自适应帧率

渲染引擎根据当前状态动态调整帧率，降低资源占用：

| 状态 | 目标帧率 | 说明 |
|:---|:---|:---|
| 动画播放中 | 60fps | 确保动画流畅 |
| 闲时（呼吸/微动） | 30fps | 维持基本动态效果 |
| 完全静止 | 15fps | 仅维持渲染循环 |
| 窗口被遮挡/最小化 | 暂停渲染 | 不消耗 GPU 资源 |

### 3.2 设计原则

- 桌面宠物为常驻后台进程，闲时资源占用应尽量低
- 不设硬性内存/CPU 上限，但设计上避免资源泄漏（纹理及时释放、音频缓存有上限）
- 渲染引擎主循环使用 `glfwWaitEventsTimeout` 而非 `glfwPollEvents`，闲时降低 CPU 轮询频率
