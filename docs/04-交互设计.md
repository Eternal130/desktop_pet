# 交互设计

> 本文档描述点击事件处理流程和拖拽行为设计。
> 整体架构参见 [架构总览](./00-架构总览.md)。

---

## 一、点击事件处理流程

### 1.1 MVP 事件流向

MVP 阶段渲染引擎独立处理点击事件，不涉及外部通信：

```plain
用户点击屏幕
     │
     ▼
┌─────────────────────────────────────────┐
│  GLFW 窗口接收鼠标事件                   │
│  (获取屏幕坐标)                          │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  交互处理层：坐标转换                    │
│  (屏幕坐标 → 模型本地坐标)               │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  Cubism SDK HitTest                     │
│  (检测点击了哪个 HitArea)                │
│  - Head (头部)                          │
│  - Body (身体)                          │
│  - Face (脸部)                          │
│  - ...                                  │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  渲染器直接处理反馈                      │
│  - 根据 HitArea 查找对应动作组           │
│  - 播放点击动画                          │
│  - 触发表情变化                          │
└─────────────────────────────────────────┘
```

> **MVP 简化**：HitArea 到动作组的映射硬编码在渲染器中（如 Head → TapHead、Body → TapBody）。后期由控制面板通过 `model_config.json` 动态配置。

### 1.2 后期事件流向（引入控制面板后）

```plain
渲染器处理即时反馈（同 MVP）
     │
     ▼
上报事件到控制面板（type: "hit", payload: { area_id, x, y, button }）
     │
     ▼
控制面板业务逻辑（记录交互、触发对话气泡等）
     │
     ▼
控制面板下发后续指令（play_motion / set_expression）
```

### 1.3 设计要点

**即时反馈由渲染器处理**：用户点击后需要立即看到反馈，这一原则在 MVP 和完整版本中一致。MVP 中渲染器是唯一处理方，后期引入控制面板后渲染器仍负责即时反馈，控制面板负责后续业务逻辑。

## 二、拖拽行为设计

### 2.1 拖拽跟随模式

支持两种拖拽跟随模式：

| 模式 | 说明 | 体验 | MVP |
|:---|:---|:---|:---:|
| **直接跟随** | 窗口位置 = 鼠标位置 - 点击偏移量 | 精确、无延迟 | ✓（默认） |
| **物理惯性** | 窗口以弹性动画跟随鼠标，带惯性和阻尼效果 | 生动、有趣味 | ✓ |

> **MVP**：拖拽模式硬编码（默认直接跟随），后期由控制面板设置面板切换。

### 2.2 MVP 拖拽流程

```plain
用户按住模型
     │
     ▼
┌─────────────────────────────────────────┐
│  渲染器检测到鼠标按下 + 拖拽             │
│  - 记录点击偏移量                        │
│  - 不切换动作（保持当前动作）             │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  持续拖拽                                │
│  - 根据跟随模式更新窗口位置              │
│  - 直接跟随：窗口即时到位                │
│  - 物理惯性：弹性动画追随鼠标            │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  用户释放鼠标                            │
│  - 窗口停在释放位置                      │
└─────────────────────────────────────────┘
```

> **后期增加**：拖拽开始/结束时上报 `drag_start` / `drag_end` 事件到控制面板，由控制面板记录位置用于崩溃恢复和持久化。

### 2.3 设计要点

- **释放后行为**：窗口停在释放位置，不做贴边吸附或重力下落
- **拖拽动作**：拖拽期间不播放特殊动作，保持当前动作继续
- **位置记录**（后期）：每次拖拽结束后控制面板记录最终位置，用于崩溃恢复和持久化
