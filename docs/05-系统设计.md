## 一、容错与错误处理

### 1.1 渲染器崩溃恢复

```plain
控制面板检测到渲染器进程退出（非正常关闭）
     │
     ▼
等待短暂冷却（避免快速循环崩溃）
     │
     ▼
重新启动渲染器进程
     │
     ▼
等待 WebSocket 连接建立
     │
     ▼
发送 hello 握手 → 等待 ready
     │
     ▼
发送 load_model（使用崩溃前的模型路径）
     │
     ▼
发送 set_position（恢复到崩溃前的窗口位置）
     │
     ▼
恢复完成，宠物回到崩溃前的状态和位置
```

**关键**：控制面板始终维护当前模型路径和窗口位置的内存副本，不依赖渲染器侧的状态。

### 1.2 WebSocket 断连处理

| 阶段 | 行为 |
|:---|:---|
| 检测 | 心跳超时（连续 N 次 ping 未收到 pong）触发断连判定 |
| 重连策略 | 指数退避重连（1s → 2s → 4s → 8s → 最大 30s） |
| 断连期间指令处理 | 缓存关键指令（`load_model`），丢弃非关键指令（`play_motion`、`set_expression` 等） |
| 重连成功 | 重发缓存的关键指令，发送状态同步（当前模型、位置、音量等） |

### 1.3 模型加载失败

```plain
控制面板发送 load_model
     │
     ▼
渲染器上报 model_load_failed（含 error_code）
     │
     ▼
控制面板处理：
  1. 弹窗通知用户加载失败原因
  2. 自动尝试加载上一个成功的模型
     │
     ├─ 上一个模型加载成功 → 恢复正常
     └─ 上一个模型也失败 → 保持无模型状态，通知用户
```

## 二、配置文件设计

### 2.1 格式

所有配置文件统一使用 **JSON** 格式，与 WebSocket 协议保持一致。

### 2.2 用户配置 (config.json)

存储路径：`~/.config/desktop-pet/config.json`

```json
{
  "window": {
    "position_x": 1200,
    "position_y": 600,
    "opacity": 1.0
  },
  "model": {
    "current_model_path": "models/haru/haru.model3.json",
    "scale": 1.0
  },
  "audio": {
    "volume": 0.8,
    "muted": false
  },
  "behavior": {
    "drag_mode": "direct",
    "idle_interval_seconds": 10
  },
  "system": {
    "auto_start": false
  }
}
```

| 字段 | 类型 | 默认值 | 说明 |
|:---|:---|:---|:---|
| `window.position_x` | int | 屏幕右下角 | 窗口 X 坐标 |
| `window.position_y` | int | 屏幕右下角 | 窗口 Y 坐标 |
| `window.opacity` | float | 1.0 | 窗口透明度 (0.0-1.0) |
| `model.current_model_path` | string | 默认模型 | 当前模型路径 |
| `model.scale` | float | 1.0 | 模型缩放比例 |
| `audio.volume` | float | 0.8 | 音量 (0.0-1.0) |
| `audio.muted` | bool | false | 是否静音 |
| `behavior.drag_mode` | string | "direct" | 拖拽模式："direct" (直接跟随) / "physics" (物理惯性) |
| `behavior.idle_interval_seconds` | int | 10 | 闲时动作触发间隔（秒） |
| `system.auto_start` | bool | false | 开机自启 |

### 2.3 模型行为映射 (model_config.json)

每个模型目录下一份，定义该模型的点击响应和闲时行为：

```json
{
  "model_path": "models/haru/haru.model3.json",
  "hit_actions": {
    "Head": { "motion_group": "TapHead", "priority": 2 },
    "Body": { "motion_group": "TapBody", "priority": 2 }
  },
  "idle_motions": ["Idle", "IdleBreath"],
  "default_expression": "default"
}
```

| 字段 | 说明 |
|:---|:---|
| `hit_actions` | 点击区域 → 触发动作的映射。key 为 HitArea 名称，value 包含动作组名和优先级 |
| `idle_motions` | 闲时可用的动作组名列表，随机选择播放 |
| `default_expression` | 模型加载后的默认表情 |

## 三、日志体系

### 3.1 设计原则

- 两端统一使用结构化日志，便于问题排查
- 日志输出到文件和控制台，文件按大小轮转
- 日志级别可通过配置文件动态调整，无需重新编译/重启

### 3.2 日志框架

| 端 | 框架 | 说明 |
|:---|:---|:---|
| C++ 渲染引擎 | spdlog 1.14.x | 高性能 C++ 日志库，支持格式化输出、多 sink（控制台 + 文件）、异步写入 |
| Java 控制面板 | SLF4J 2.0.x + Logback 1.5.x | SLF4J 门面解耦日志 API，Logback 提供实现，支持 XML 配置、轮转策略 |

### 3.3 日志级别定义

| 级别 | 适用场景 | 示例 |
|:---|:---|:---|
| ERROR | 影响功能的错误，需要关注 | 模型加载失败、WebSocket 连接异常断开、音频播放器初始化失败 |
| WARN | 异常但可恢复的情况 | 重连尝试、配置字段缺失使用默认值、非关键指令丢弃 |
| INFO | 关键业务节点 | 启动完成、模型切换、WebSocket 握手成功、渲染器进程启动/退出 |
| DEBUG | 开发调试信息 | 消息收发内容、状态变更详情、定时任务触发 |
| TRACE | 高频细粒度信息 | 每帧渲染耗时、鼠标坐标变化、参数引擎每帧计算值 |

### 3.4 日志文件管理

| 项目 | 配置 |
|:---|:---|
| 存储路径 | `~/.config/desktop-pet/logs/` |
| 文件命名 | `controller.log`（Java 端）、`renderer.log`（C++ 端） |
| 轮转策略 | 单文件上限 10 MB，保留最近 5 个归档文件 |
| 默认级别 | Release 构建默认 INFO，Debug 构建默认 DEBUG |
| 控制台输出 | Debug 构建同时输出到控制台，Release 构建仅文件 |

### 3.5 关键日志点

**控制面板（Java）**：

- 应用启动/关闭
- 配置文件加载（路径、关键配置值）
- WebSocket 连接/断开/重连（含重连次数和间隔）
- 渲染器进程启动/退出（含退出码）
- 指令发送（action + id，DEBUG 级别含完整 payload）
- 事件接收（action + id）

**渲染引擎（C++）**：

- 引擎初始化（OpenGL 版本、窗口参数、Cubism SDK Core 版本 `csmGetVersion()`、支持的最高 moc3 版本 `csmGetLatestMocVersion()`）
- WebSocket Server 启动（监听端口）
- 模型加载（路径、耗时、资源数量）
- 动作/表情切换
- 音频播放开始/结束
- 帧率变化（自适应帧率切换时记录）
- 错误及异常（含错误码）

## 四、启动流程

```plain
1. Controller (Java) 启动
   │
   ├─> 2. 加载用户配置 (config.json)
   │
   ├─> 3. 启动 Renderer 进程
   │      │
   │      └─> 4. Renderer 初始化
   │            ├─> 初始化 GLFW/GLEW
   │            ├─> Cubism SDK 初始化
   │            │     ├─> 创建 ICubismAllocator 实现（自定义内存分配器）
   │            │     ├─> CubismFramework::CubismStartUp（注册分配器 + 日志回调）
   │            │     ├─> CubismFramework::Initialize（初始化 Framework 内部状态）
   │            │     └─> 记录 SDK 版本（csmGetVersion）
   │            ├─> 创建透明窗口 (X11)
   │            └─> 启动 WebSocket Server
   │
   ├─> 5. Controller 等待 WebSocket 连接
   │
   ├─> 6. WebSocket 连接建立
   │
   ├─> 7. Controller 发送 hello 握手
   │
   └─> 8. Renderer 响应 ready（含版本和能力信息）
          │
          ├─> 9. Controller 发送 load_model（配置中的当前模型）
          │
          ├─> 10. Controller 发送 set_position（配置中的窗口位置）
          │
          └─> 11. 模型加载完成，进入主循环
```

## 五、扩展性预留

### 4.1 插件/脚本系统

未来计划支持 **Lua 脚本** 扩展宠物行为。当前版本仅做架构预留：

- 交互处理器（InteractionHandler）设计为可插拔接口，未来可由 Lua 脚本实现自定义响应逻辑
- 闲时行为的权重打分机制预留脚本注入点，允许插件注册新动作和权重函数
- 模型行为映射配置（model_config.json）的结构可扩展，未来支持脚本字段

本版本不实现 Lua 运行时和插件加载器。

### 4.2 状态系统

状态管理器（PetStateManager）预留养成属性接口，未来可引入心情、活力、好感度等属性，驱动行为决策从随机选择升级为权重打分。
