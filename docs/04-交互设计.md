## 一、点击事件处理流程

### 1.1 事件流向

```plain
用户点击屏幕
     │
     ▼
┌─────────────────────────────────────────┐
│  GLFW 窗口接收鼠标事件                   │
│  (获取屏幕坐标)                          │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  交互处理层：坐标转换                    │
│  (屏幕坐标 → 模型本地坐标)               │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  Cubism SDK HitTest                     │
│  (检测点击了哪个 HitArea)                │
│  - Head (头部)                          │
│  - Body (身体)                          │
│  - Face (脸部)                          │
│  - ...                                  │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  渲染器处理即时反馈                      │
│  - 播放点击动画                          │
│  - 播放点击音效 ← 音频播放器             │
│  - 触发表情变化                          │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  上报事件到控制面板                      │
│  type: "hit"                            │
│  payload: { area_id, x, y, button }     │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  控制面板业务逻辑                        │
│  - 记录交互记录                          │
│  - 触发后续动作 (如对话气泡)             │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  控制面板下发后续指令 (可选)             │
│  - play_motion (播放特定反应动作)        │
│  - set_expression (设置表情)            │
└─────────────────────────────────────────┘
```

### 1.2 职责划分

| 环节   | 处理方  | 说明                 |
| :--- | :--- | :----------------- |
| 坐标获取 | 渲染器  | GLFW 原生事件          |
| 坐标转换 | 渲染器  | 窗口坐标→模型坐标          |
| 碰撞检测 | 渲染器  | Cubism SDK HitTest |
| 即时反馈 | 渲染器  | 点击动画+音效（零延迟体验）     |
| 事件上报 | 渲染器  | 通知控制面板发生了什么        |
| 业务响应 | 控制面板 | 后续逻辑          |

### 1.3 设计要点

**即时反馈由渲染器处理**：用户点击后需要立即看到/听到反馈，如果等待控制面板响应再播放动作和音效，会产生明显延迟（网络传输+JSON处理），影响体验。

**业务逻辑由控制面板处理**：点击后触发对话、记录统计等业务逻辑，由控制面板根据模型配置和当前状态决定。

## 二、拖拽行为设计

### 2.1 拖拽跟随模式

支持两种拖拽跟随模式，用户可在设置面板中切换：

| 模式 | 说明 | 体验 |
|:---|:---|:---|
| **直接跟随** | 窗口位置 = 鼠标位置 - 点击偏移量 | 精确、无延迟 |
| **物理惯性** | 窗口以弹性动画跟随鼠标，带惯性和阻尼效果 | 生动、有趣味 |

### 2.2 拖拽流程

```plain
用户按住模型
     │
     ▼
┌─────────────────────────────────────────┐
│  渲染器检测到鼠标按下 + 拖拽             │
│  - 记录点击偏移量                        │
│  - 上报 drag_start 事件                 │
│  - 不切换动作（保持当前动作）             │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  持续拖拽                                │
│  - 根据跟随模式更新窗口位置              │
│  - 直接跟随：窗口即时到位                │
│  - 物理惯性：弹性动画追随鼠标            │
└─────────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────────┐
│  用户释放鼠标                            │
│  - 窗口停在释放位置                      │
│  - 上报 drag_end 事件 (含最终坐标)      │
│  - 控制面板记录新位置 (用于崩溃恢复)     │
└─────────────────────────────────────────┘
```

### 2.3 设计要点

- **释放后行为**：窗口停在释放位置，不做贴边吸附或重力下落
- **拖拽动作**：拖拽期间不播放特殊动作，保持当前动作继续
- **位置记录**：每次拖拽结束后控制面板记录最终位置，用于崩溃恢复和持久化
