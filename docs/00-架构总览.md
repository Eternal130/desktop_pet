│  ┌──────────────────────────────────────────────────────────────┐  │
│  │                   WebSocket Server                            │  │
│  └──────────────────────────────────────────────────────────────┘  │

## 三、设计原则

### 3.1 分离关注点

- **渲染引擎 (C++)** ：专注于高性能图形渲染、模型加载、动画播放、用户输入检测和音画同步
- **控制面板 (Java)** ：专注于业务逻辑、状态管理、用户配置和系统托盘交互

### 3.2 通信机制

- 采用 WebSocket 作为进程间通信协议
- 使用 JSON 格式的结构化消息，统一 Envelope 格式（详见 [通信协议](./03-通信协议.md)）
- 支持指令（控制面板→渲染器）和事件（渲染器→控制面板）双向通信
- 关键指令支持 request-response 回执确认

### 3.3 职责边界

| 职责      | 控制面板 | 渲染引擎     |
| :------ | :--- | :------- |
| 模型加载与管理 | ✗    | ✓        |
| 动画渲染    | ✗    | ✓        |
| 点击/拖拽检测 | ✗    | ✓ (底层)   |
| 音频播放    | ✗    | ✓ (同步播放) |
| 音量控制/静音 | ✓    | ✓ (响应指令) |
| 业务状态管理  | ✓    | ✗        |
| 用户配置界面  | ✓    | ✗        |
| 定时任务    | ✓    | ✗        |
| 动作触发逻辑  | ✓    | ✗        |

## 四、设计决策总结

| 方面       | 设计决策                    |
| :------- | :---------------------- |
| **整体架构** | Java 控制面板 + C++ 渲染引擎分离  |
| **通信**   | WebSocket + JSON 协议，统一 Envelope 格式，关键指令回执确认 |
| **音频播放** | 模型关联音频由渲染器播放，控制面板提供音量控制 |
| **点击事件** | 渲染器负责检测和即时反馈，控制面板负责业务逻辑 |
| **拖拽行为** | 直接跟随/物理惯性可配置，释放后停留，不切换动作 |
| **音画同步** | 在渲染器内统一处理，避免网络延迟        |
| **闲时行为** | MVP 随机选择，预留权重打分扩展        |
| **容错**   | 崩溃自动重启恢复位置，断连缓存关键指令，模型失败回退 |
| **配置**   | JSON 格式，用户配置 + 模型行为映射      |
| **性能**   | 自适应帧率（15-60fps），闲时低占用     |
| **平台**   | MVP Ubuntu/X11，后期 Windows   |
| **分发**   | 内嵌 JRE，安装包 + 免安装双形式      |
| **扩展预留** | Lua 脚本插件系统、养成状态系统         |
