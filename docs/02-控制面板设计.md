> **本文档整体不在 MVP 范围内。** MVP 阶段仅实现 C++ 渲染引擎独立运行，不包含 Java 控制面板。以下内容为 Phase 2（控制面板）和 Phase 3（音频管理）的设计方案。
>
> 本文档描述 Java 控制面板的模块设计、技术选型和闲时行为策略。

## 二、模块概览

### 2.1 UI 层（JavaFX）

使用 JavaFX 25 构建用户界面，采用 FXML + CSS 分离布局与样式：

- **主界面（MainWindow）**：宠物当前状态显示、快捷操作按钮。继承 `javafx.application.Application`，作为 JavaFX 生命周期入口
- **设置面板（SettingsPanel）**：音量调节（Slider）、模型选择（ListView）、行为配置、启动项设置、拖拽模式切换（ToggleGroup）。使用 FXML 布局 + CSS 样式表定制外观
- **系统托盘（TrayIcon）**：使用 `java.awt.SystemTray` API（JavaFX 未提供原生托盘支持），最小化到托盘、右键菜单（退出、显示/隐藏、快捷设置）
- **宠物管理**：模型切换（FileChooser 选择模型目录）、模型导入
- **音频管理（Phase 3）**：音频文件导入/删除（FileChooser）、音频映射配置（为模型的动作组指定音频文件）、音量滑块（Slider）与静音开关。音频文件与模型文件分离存储，支持跨模型复用同一音频

**UI 架构要点**：

| 关注点 | 方案 |
|:---|:---|
| 布局定义 | FXML 文件（`src/main/resources/fxml/`），通过 `FXMLLoader` 加载 |
| 样式管理 | CSS 样式表（`src/main/resources/css/`），支持运行时主题切换 |
| 事件绑定 | FXML Controller 类，使用 `@FXML` 注解绑定 UI 组件 |
| 线程安全 | UI 更新必须通过 `Platform.runLater()` 回到 JavaFX Application Thread |
| 可视化设计 | 推荐使用 JavaFX Scene Builder 辅助设计 FXML 布局 |

### 2.2 业务逻辑层

- **状态管理器（PetStateManager）**：维护宠物配置和运行时状态。MVP 阶段不实现心情/活力/好感度等养成属性，闲时行为从模型可用动作中随机选择。架构预留权重打分扩展，未来可根据状态属性值计算动作权重。使用 Java Records 定义不可变状态快照
- **交互处理器（InteractionHandler）**：接收渲染器上报的 `hit` 事件，查询模型行为映射配置（`model_config.json`），决定后续响应（如下发 `play_motion` 指令）。设计为可插拔接口，预留未来 Lua 脚本扩展
- **定时任务（Scheduler）**：使用 `java.util.concurrent.ScheduledExecutorService` 实现定时闲时动作触发。可配置触发间隔（默认 10 秒）
- **配置管理器（ConfigManager）**：基于 Gson 读写 JSON 配置文件（`~/.config/desktop-pet/config.json`），支持配置热更新和导入导出。详见 [系统设计 - 配置文件](./05-系统设计.md)
- **音频映射管理器（AudioMappingManager）**（Phase 3）：管理音频文件与模型动作的映射关系。读写 `audio_mapping.json` 配置，在模型加载后通过 `set_audio_mapping` 指令将映射下发给渲染器。支持跨模型复用音频文件（同一音频可被多个模型的不同动作引用）

### 2.3 通信层（Network Layer）

基于 Java-WebSocket 库实现 WebSocket 客户端：

- **WebSocketClient**：封装连接建立、消息收发、心跳检测逻辑。使用独立线程处理网络 I/O，避免阻塞 UI 线程
- **MessageDispatcher**：按消息 `type`（event / response）和 `action` 路由到对应的处理器。采用注册式分发机制（Handler Map）
- **Protocol**：封装 Envelope 格式的序列化/反序列化（Gson），提供类型安全的消息构建 API
- **断连处理**：心跳超时检测 + 指数退避重连（1s → 2s → 4s → 8s → 30s 上限）。断连期间缓存关键指令（`load_model`），重连后重发。详见 [系统设计 - 容错](./05-系统设计.md)

### 2.4 进程管理器（ProcessManager）

负责渲染器进程的生命周期管理：

- 使用 `ProcessBuilder` 启动渲染器可执行文件，捕获其 stdout/stderr 输出并转发到日志
- 通过 `Process.onExit()` 监听进程退出，区分正常关闭与异常崩溃
- 崩溃自动重启：冷却等待 → 重启渲染器 → 等待 WebSocket 连接 → 重发模型和位置恢复指令
- 应用关闭时通过 `shutdown` 指令优雅终止渲染器，超时后 `Process.destroyForcibly()` 兜底，避免孤儿进程

## 三、闲时行为设计

### 3.1 MVP 方案

MVP 阶段不实现宠物养成状态系统（心情/活力/好感度）。闲时行为采用简单随机策略：

```plain
定时任务触发（ScheduledExecutorService）
     │
     ▼
从模型可用的闲时动作池（idle_motions）中随机选择一个
     │
     ▼
下发 play_motion 指令到渲染器
```

### 3.2 扩展预留

架构预留权重打分决策机制，未来引入状态系统后：

```plain
定时任务触发
     │
     ▼
获取当前状态属性（心情、活力、好感度...）
     │
     ▼
为每个候选动作计算权重分
  - 心情高 + 活力高 → 欢快动作权重高
  - 心情低 + 活力低 → 打瞌睡/委屈动作权重高
     │
     ▼
加权随机选择动作
     │
     ▼
下发 play_motion 指令
```

状态数据支持持久化（关闭应用后下次启动可从上次状态继续），具体状态属性和衰减规则待未来版本设计。
